# Implementation Plan: Native GPU Acceleration

**Branch**: `001-gpu-acceleration` | **Date**: 2026-05-10 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `specs/001-gpu-acceleration/spec.md`

## Summary

Port the mojo-md simulation loop to run end-to-end on GPU using Mojo's `std.gpu` / `std.gpu.host` API, with data resident in `DeviceBuffer` arrays throughout the hot path. Atom positions are copied CPU→GPU at initialisation; the only CPU transfers during a run are (a) at ghost+neighbour-list rebuild steps (atom positions copied GPU→CPU, new ghosts+nlist copied CPU→GPU) and (b) at print/save-state steps (scalars only). A `--gpu` CLI flag enables the GPU path; absent the flag on a GPU-equipped machine, a stderr warning is printed. A standalone benchmark script (`bench.mojo`) runs LJ and Vashishta across a fixed size ladder on both backends and reports Matom·steps/s.

## Technical Context

**Language/Version**: Mojo 0.26.x  
**Primary Dependencies**: `std.gpu`, `std.gpu.host`, `layout` (TileTensor), `std.sys.has_accelerator`, `std.algorithm.parallelize` (CPU path unchanged)  
**Storage**: N/A (JSON config read via Python interop; trajectory output to stdout)  
**Testing**: `mojo run -I . test/test_*.mojo` (existing suite); GPU tests require GPU hardware  
**Target Platform**: macOS + Linux, NVIDIA/AMD GPU  
**Project Type**: CLI simulation binary  
**Performance Goals**: ≥5× GPU speedup over CPU at 50k+ atoms (LJ); Matom·steps/s as the primary benchmark metric  
**Constraints**: Zero CPU↔GPU transfers during non-rebuild time steps; neighbour list build is the one allowed CPU round-trip per `rebuild_interval` steps (acknowledged as "absolutely necessary" in spec — GPU-side neighbour list is out of scope for this PR)  
**Scale/Scope**: Up to 10 million atoms in benchmark; production runs typically 10k–1M atoms
